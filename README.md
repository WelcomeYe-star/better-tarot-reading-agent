# 塔罗占卜 Agent（Tarot Reading Agent）

一个对话式塔罗牌占卜解读技能包，基于**韦特塔罗（Rider-Waite Smith，78 张牌）**体系。

用户提一个问题 → Agent 判断该抽几张牌 → 引导用户用实体牌抽牌 → 用户报牌名 + 正逆位 → Agent 结合**牌阵、元素、占星旬星、数字学、画面符号**等多个维度，给出贴合个人感受、轻松有启发的解读。

> 不只是"报牌→解牌"，而是一套完整的引导式占卜流程：问题定性、牌阵选择、逐张抽牌引导、口语报牌归一化、多维深度解读，并内置严谨的**占卜适用范围边界**。

---

## 特点

- 🎴 **78 张牌完整知识库**：每张含牌名/别名/牌号/大类/花色/元素/占星对应/数字象征/正逆位关键词与详解/**画面符号**
- 🔭 **黄金黎明旬星体系**：数字牌按 36 个 decan 精确对应（如「圣杯二＝金星在巨蟹 · 巨蟹 0°–10°」），宫廷牌用「元素之元素」（如「权杖皇后＝火中之水」）
- 🃏 **6 种牌阵**：单牌、三牌（含时间线/身心灵/情况-行动-结果三种变体）、四元素、关系、马蹄形（7 张）、凯尔特十字（10 张）
- 🧠 **多维解读引擎**：元素平衡、花色缺席、大阿卡纳占比、正逆位分布、主题共振、**位置×元素交互**
- 📏 **长度有谱**：按牌阵规模自动定字数预算（单牌 200–350 字，十张 1200–1800 字），四层结构输出，关键牌细读、其余只给一句定位
- 🔄 **逆位四取向**：削弱／阻滞／内化／过度，按牌性、位置语义、元素与位置冲突加权判定，给出可解释的理由，而不是一律读成"反面"
- 🗣️ **口语报牌归一化**：支持「逆位愚者」「倒牌女祭司」「钱币三」「杯中二」「星币王后」「大阿卡纳14号」「The Fool」等各种说法
- 🩹 **抽牌异常兜底**：说不出牌名（按画面反推候选）、报错牌、重复牌、数量不对、中途改问题、没有实体牌……11 类岔子各有处理方式，原则是不重置对话
- 🛡️ **严谨边界**：明确区分"适合占卜 / 不适合但可引导 / 不能占卜"三类问题，涉及医疗、法律、人身安全等直接拒绝并引导求助
- 💬 **有人味**：轻松、缓和、活泼的语气，淡化说教，落脚在共情与启发

## 快速开始

### 方式一：作为 WorkBuddy 技能安装

1. 将 `tarot/` 目录复制到你的技能目录：`~/.workbuddy/skills/tarot/`
2. 重启 / 刷新 WorkBuddy 会话
3. 对话中直接说："帮我占卜一下……"，即会自动触发

### 方式二：直接调用引擎

```bash
node scripts/tarot_engine.js
```

自检会跑归一化、逆位取向、画面反推、抽牌告警四组用例，检查 78 张牌字段完整性，最后输出一份示例解读上下文。

```js
const E = require('./scripts/tarot_engine.js');

const { cards, aliases } = E.loadAllCards();
const cid = E.resolveCard('逆位节制', aliases);           // -> 'major-14'
const ori = E.detectOrientation('逆位节制', aliases);      // -> 'reversed'
const ctx = E.buildReading(cards, [{ card_id: cid, orientation: ori }]);

console.log(E.formatContext(ctx));
```

### 方式三：不跑脚本

引擎只是辅助。JSON 字段设计已保证可以直接人工汇总——Agent 读数据自己算也完全可行。技能在没有 Node 的环境里同样可用。

## 完整占卜流程

1. **问题定性**：领域、类型、复杂度
2. **占卜范围判定**：适合 / 可引导 / 拒绝
3. **选择牌阵**（内部决策，不剧透结构）
4. **逐张抽牌引导**（主动告知总张数，保持神秘感与直觉）
5. **报牌归一化**（牌名/牌号/英文名/花色变体/正逆位口语）
6. **深度解读**（按规模定长度，四层结构：核心 → 故事线 → 关键牌细读 → 小结；元素 + 数字 + 占星 + 画面符号融入其中）

## 数据字段

| 字段 | 说明 |
|---|---|
| `element` | 火 / 水 / 风 / 土 |
| `astrology` | 数字牌为旬星行星-星座；王牌为元素之根；宫廷牌为元素之元素 |
| `numerology` | 数字象征，含卡巴拉源质层（Kether→Malkuth） |
| `symbols` | 韦特牌面符号 4–5 个，附象征义 |
| `reversal_profile` | 逆位取向档案：primary/secondary + 一句提示 |
| `keywords_upright` / `meaning_upright` | 正位关键词与详解 |
| `keywords_reversed` / `meaning_reversed` | 逆位关键词与详解 |
| `aliases` | 口语别名（花色/数字/宫廷变体由引擎结构化解析，无需穷举） |

## 设计理念

这套工具的核心不是"算得准不准"，而是把塔罗当作**一面照见自己的镜子**——通过牌阵结构和知识维度，帮助用户以新的角度理解当下的处境与内心。因此：

- 解读**指向自己、指向当下、答案开放、有行动余地**
- 语气**淡化说教**，呈现知识本身，让用户感到"被理解"而非"被分析"
- 明确**边界**：塔罗推不出客观事实和他人的内心，也绝不替代专业医疗/法律/心理建议
- **牌阵位置只谈你**：关系牌阵里不设"对方在想什么"的位置，因为那超出了塔罗能回答的范围

## 变更日志

### 2.4.0

**新增**
- **解读长度分层**：按牌阵规模给出字数预算——单牌 200–350、三张以内 450–750、四五张 650–950、六七张 900–1300、八到十张 1200–1800
- 输出结构改为**四层**：一句话核心 → 故事线 → 关键牌细读 → 塔罗视角小结
- `planReading(ctx)`：按规模算出预算与分层，并挑出**值得细读的关键牌**（大阿卡纳／逆位／落在核心位置），其余牌只给一句定位
- **维度颗粒度规则**：元素、占星、数字改为**阵级讲分布**，画面符号保留**逐张讲**。四个维度仍须全部出现，但不必每张牌都讲四个
- 「什么时候停下来」：要点太密、用户在追某个点、情绪起伏大、只想要一句话——四种情况主动缩短

**设计取舍**
- 分层减的不是"维度数量"，而是"维度颗粒度"。元素、占星、数字本质是分布性的，逐张报反而稀释信息；符号是具体画面，落到单张才有效
- 宁可讲得少而准，不要讲得多而平。十张牌全展开会到三四千字，那不是专业，是没剪裁

### 2.3.0

**移除**
- 移除 `tarot_engine.py`，只保留 `tarot_engine.js` 单一引擎
- 原因：Python 版在 2.0–2.2 三轮迭代中始终无法在目标环境实机验证（机器上没有可用的 Python 运行时）。留一个跑不了、也没人测的副本，比不留更糟——它只会让文档承诺和实际能力再次脱节
- 引擎不是必需品：JSON 字段设计已保证无脚本也能人工汇总，技能在无 Node 环境同样可用
- `LICENSE.md` 许可条款同步改为「`scripts/` 下的代码」

### 2.2.0

**新增**
- **抽牌阶段异常处理**：11 类常见岔子——牌名说不出、报了不存在的牌、重复牌、数量不对、一次全报完、中途改问题、中途加抽/减抽、抽牌时杂问、用户先下结论、情绪激动、想中途停止——每类给出判断与话术
- **没有实体牌的三种替代**：扑克牌对应、报数字虚拟抽牌、不抽只聊。但必须先问，不擅自替用户虚拟抽牌
- `matchByImagery(desc)` 画面反推：用户说不出牌名时，按"一个人站在悬崖边"这类描述反推候选，实测 Top1 命中 5/6、Top3 命中 6/6
- `checkDrawWarnings()` 抽牌校验：重复牌、未识别牌，`formatContext` 会输出【抽牌告警】置顶提示

**设计取舍**
- 画面反推不追求 Top1 准确，定位是"给 2–3 个候选让用户认"——直接断定比给三个选项更容易出错
- 中途改问题分三种进度处理，底线是**绝不用旧牌硬解新问题**
- 所有异常的共同原则：先接住，再往下走，**不重置对话、不让用户从头再来**

### 2.1.0

**新增**
- **逆位四取向**：削弱／阻滞／内化／过度。78 张牌各带 `reversal_profile`（最常呈现的样子 + 次常见 + 一句洞察提示）
- 取向判定引擎：四类信号加权——牌性档案、牌阵位置语义、元素外向/内向倾向、位置与元素是否对冲，输出候选排序、理由与置信度
- `formatContext` 新增【逆位取向】段落，含"每张只讲一种，不要四种都罗列"的约束

**设计取舍**
- 引擎只给候选和理由，不替 Agent 做最终判断——置信度为 `low` 时会显式提示"更该听用户自己怎么描述"
- 取向不等于"好/坏"：阻滞讲的是卡住的那个点，过度讲的是失衡，都不带指责

### 2.0.0

**修复**
- 正逆位判定改为「先剔除牌名、再判方位」，修掉「倒吊人」被判为逆位、「正义」被判为正位的误判
- 报牌归一化改为「最长别名匹配 + 结构化解析」，修掉「大阿卡纳14号」不被支持、读不出「钱币三」「杯中二」「星币王后」的问题
- 修掉三牌阵声明「身-心-灵」却没有对应位置的矛盾
- 主题共振不再把正逆位关键词混算
- 关系牌阵第 2 位由「对方的感受」改为「你感受到的张力」，与技能自身的边界规定保持一致
- 引擎由 Python 单实现改为 JS 首选 + Python 兼容，避免环境无 Python 时完全跑不起来（该 Python 兼容版已于 2.3.0 移除）

**新增**
- 56 张小阿卡纳补齐 `astrology`（黄金黎明旬星）/ `numerology`（源质层）/ `symbols`（韦特画面符号），78 张牌字段全覆盖
- 花色缺席分析：缺哪种元素的语言，就是这件事里缺席的那种能力
- 位置×元素交互：同频 / 对冲 / 互补三种关系判定
- 三牌阵三种变体：时间线、身-心-灵、情况-行动-结果
